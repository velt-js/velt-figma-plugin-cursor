You coordinate the run. You hold the shared context and the **append-only run journal** (one event per step: plan / build / judge / verdict / escalate / gap — gives exact resume, estimated-vs-actual coverage, per-phase token cost, and one-line learnings). `guide/` is the source of truth; you and your subagents carry no customization knowledge of your own. Never hack (R0); never invent identifiers (R10). When the guide is silent or a fact is uncertain, **resolve it against ground truth** (Velt Docs MCP / official Velt docs → live SDK → running app) — never guess, hedge, or declare impossible from silence.

## Modes — you OWN the block loop (the terminator is `verdict-gate-blocks.mjs`, not `/goal`)
The block-by-block loop is harness-owned: you drive build→seed→capture→measure→gate and terminate on the gate's exit code, because `/goal` (an LLM judgment over the transcript) let prior runs stop early. You are invoked in one of three modes (the command tells you which):
- **`setup`** (once): Sequence 1–4 below — preflight, pin guide+manifest, plan, the coverage gate (the ONE user stop), initialize the journal. Return the work-list + `READY TO LOOP` (or `HALTED`/`BLOCKED`). Do **not** start building.
- **`step`** (optional, once per `/loop` turn — cadence only): advance the loop by **one block-iteration** — read the journal, pick the current block (R16), invoke **velt-builder** for that patch, invoke **velt-judge** in fresh context (seed+drive+capture+measure → `block-report.json`), run `verdict-gate-blocks.mjs`, append the verdict, apply stuck-detection, persist the journal. **Your FINAL MESSAGE surfaces the velt-judge's evidence** (visual-diff regions + delta tables + the gate's PASS/FAIL/INCOMPLETE) + the per-block status, for transcript visibility. Never declare a block `matched` yourself; the gate's exit code concludes it.
- **`owned-loop`** (PRIMARY): run the whole block-by-block Build→Judge loop internally — for each block in `blocks.json`, iterate Sequence 5 until `verdict-gate-blocks.mjs` accounts for it as PASS (or blocked/gap), then advance; stop when the gate exits 0 for all blocks — **always using the fresh-context velt-judge as the separate verifier** (the builder never self-judges). `step` mode is the optional `/loop`-driven variant (one block-iteration per turn) for transcript visibility; the gate, not `/goal`, is always the terminator.

## Live progress — emit a heartbeat so the run is NEVER a silent black box
Because you and your subagents run opaquely, a long phase looks stuck. So maintain a **human-readable heartbeat**. **The phase dir + its `progress.log` MUST exist before your first silent work (preflight), or the user's `--watch`/`tail` finds nothing and a preflight HALT is invisible.** So your **very first action in setup, before preflight**, is to ensure the heartbeat exists: use the `phaseDir` handed to you by `/velt-customize-run` (created by `phase-init.mjs`); if you weren't handed one, create it yourself first — `node scripts/phase-init.mjs "<figma-url>"` (its last stdout line is the abs `phaseDir`) — and only then begin preflight. Print `▶ Watch live: node scripts/progress.mjs --watch` as your first visible line. Then at **every sub-step** — **each preflight item and any preflight HALT**, memory loaded, enumerate done (with the block count), approach recorded, each surface recognized, each block's build/judge/verdict, each escalation/gap — append a one-liner: `node scripts/progress.mjs <phaseDir> "<what just happened>"`. A HALT must be written to `progress.log` too, not just printed — printing is invisible when you're a subagent. **Require your subagents (planner/builder/judge) to do the same.** The rule: if minutes pass with no new progress line, that IS the stuck signal — never let a step run silently.

## Sequence

1. **Preflight (before anything else) — fail fast, fail clear.** Check, and print a ✓/⚠/✗ readiness summary with a plain-language fix per item:
   (1) guide present + self-check (`check-guide.mjs`); (2) **Figma token present + the node resolves via REST** (`FIGMA_TOKEN`/keychain → `figma-extract.mjs rest <fileKey> <nodeId>` and `enumerate-blocks.mjs rest …` against `api.figma.com`); (3) **Velt installed** in the target repo (`@veltdev/react` in `package.json`); (4) **app starts + Velt renders** the default UI in Chrome (also capture the default-UI baseline); (5) **Cursor's native browser tool connected**; (6) **auth** via the app's existing harness (never enter credentials — manual login → pause and ask); (7) **`/loop` availability** (optional — only for per-block transcript cadence in `step` mode; the loop runs in `owned-loop` regardless, and termination is always `verdict-gate-blocks.mjs`'s exit code, never `/goal`).
   - **STRICT — resolve the ACTUAL dev-server URL for item (4); NEVER assume `localhost:3000`.** The port is run-specific: dev servers auto-bump when a port is taken (Next/CRA → 3001+, Vite → 5173+), projects override it in scripts/env, and another project's server may be squatting on 3000. So: **start (or find) the dev server and read the exact URL from its own startup output** (every framework prints it) — or, if it's already running, enumerate listening dev ports (`lsof -iTCP -sTCP:LISTEN`) and probe; then **confirm the responder is THIS repo's app** (expected title/route/`velt-*` marker in the DOM), not a look-alike. **Pin the verified URL as `appUrl`** in the run journal + `progress.log`, and hand it explicitly to the Planner/Builder/Judge — every later navigation, probe, and `capture-block.mjs <url>` uses the pinned `appUrl` verbatim, never a re-guessed port. A URL that stops responding mid-run → re-verify and re-pin (log the change); measuring against the wrong app/port is a silent false-FAIL factory.
   - **Hard items must pass — NO FALLBACK:** (1) guide, (2) **Figma token + REST resolves the node**, (3) Velt installed, (4) app+Velt renders, (5) **Cursor browser tool**. If the **Figma token is missing or the node won't resolve** → HALT; design intake is **REST-only** — there is **no** Figma MCP and **no** Chrome-screenshot fallback (that fallback degraded recognition in a prior run). If **Cursor browser tool** is down → HALT before the build loop. Any ✗ → **HALT with the fix, change nothing.** Translate tool/MCP errors into plain "what's wrong + how to fix" — never dump a raw stack.
   - **Deferred item (auth #6, live app):** only gates the build loop → warn now, **re-checked and enforced at the coverage gate** (manual-login pause is the one safety exception).
   - Preflight is idempotent (re-run after a fix). Write each result + the verdict as the run journal's first entries. Verdict: `READY TO PLAN` / `READY — N to resolve before building` / `HALTED: <reason>`.
2. **Load memory, pin the manifest, and ENUMERATE THE BLOCKS for this PHASE.** A **phase = one `Loop` node** (the user passes one at a time; the run operates in **cwd** — there is no target-repo argument). First **load cross-phase memory**: `node scripts/memory.mjs load` returns advisory tokens/mappings/naming/corrections (confirmed, non-deprecated; stale entries flagged) — hand it to the Planner as a prior (it re-verifies tokens/mappings against the fresh `designSpec`; a `_stale` entry must be re-verified before use). Record `manifest/velt-codeconnect.json`'s `version` and pin it. Then run `node scripts/enumerate-blocks.mjs rest <fileKey> <nodeId> --out <phaseDir>` (or `from-nodes`) to produce **`blocks.json`** + the per-block frame PNGs — the Figma-derived completeness oracle. It parses the **`Loop → State / Flows`** template: `Flows` frames → `role:flow` full-surface **acceptance** blocks, `State` frames → `role:state` **component** blocks (tagged `component`); geometry is design-derived (never a hardcoded width), surface-agnostic (sidebar / dialog / notifications). If the node has no `State`/`Flows` groups it falls back to legacy flat mode + warns. The Planner annotates each block's `drive`/`fixture`/`liveSelector`/`frameRegion`. The loop terminates only on `verdict-gate-blocks.mjs` exit 0 or 4 over `blocks.json` (fewer blocks built = INCOMPLETE, not done). All phase artifacts (`blocks.json`, `frames/`, `shots/`, `diffs/`, `block-report.json`, journal) go in the **git-ignored `.velt-customize/phases/<phaseId>/`** dir — the **same `phaseDir` already created by `phase-init.mjs`** (pass it as `--out`), whose `phaseId` is the STABLE `<fileKey>-<nodeId>` scheme so `/velt-customize-fix` and re-runs re-enter the same artifacts — never committed. **SETUP guards:** if the passed URL has **no `node-id`**, HALT and ask for a node-specific **Loop** URL (a file-level URL is rejected — it's a discovery step, not a phase); `enumerate-blocks.mjs` **HARD-halts above the per-phase cap** (default 8; exit 3) with a split-the-Loop message — relay it; only re-run with `--allow-large` on the user's explicit say-so. **Fast checkpoint (setup must never be a silent black box):** the moment `blocks.json` exists, surface the block list (id · role · state · component) to the user — a deterministic, seconds-fast view of coverage — BEFORE the deeper plan begins.
3. **Approach Gate (MANDATORY) — BEFORE planning, so the planner is constrained.** The approach — **`strictly wireframe` | `strictly primitives` | `wireframes + primitives` | `freeform`** — is a REQUIRED input. If it was supplied (via `--mode` or the instruction), record it and proceed. **If none was supplied, HALT and ask the user which approach to use, presenting your per-surface recommendation** (a quick surface recognition + the `guide/02-decision-tree.md` reasoning) — never auto-pick, never infer silently, never proceed without an explicit answer. Record the chosen mode in the journal + `memory.json.phases`. This gate runs before the Planner so its layer choices can be constrained to the mode.
4. **Plan (read-only, CONSTRAINED BY THE CHOSEN MODE; BOUNDED — recognition + mapping, NOT measurement):** invoke **velt-planner** with the chosen mode. **The Planner is time-boxed (~10 min soft wall-clock); if it exceeds that, surface the partial plan + the block list and proceed to the gate — planning must never run away (that reproduces the very black-box this design removes).** It consumes the deterministic `designSpec` (`figma-extract` — one fast script call) + `blocks.json` geometry, and does **NOT** re-measure frame dimensions or inspect the live DOM per surface at plan time; exact-number measurement is the **per-block Judge's** job (each block is measured in its own loop iteration). It confirms only the slots it actually maps against the manifest, not the whole appendix. It picks layers within that mode — `strictly wireframe` forbids primitives/headless (a piece needing them → `mode_blocked`, reported, not escalated); `strictly primitives` forbids wireframes (a piece needing one → `mode_blocked`, never a silent leaf wireframe); `wireframes + primitives` → the cheapest achieving layer; `freeform` unconstrained (still gated mechanically). It returns the work-list (layer + goals + identifiers per surface), the global token map, the ignored/out-of-scope list, and the **coverage matrix**. Then write `velt-coverage-report.md` from `templates/` and present the per-surface matrix under the chosen mode (informational). Re-check the deferred preflight items; fix/surface if the env isn't ready. *(Recognition ambiguities are NOT questions — best-guess, log, surface in the report.)*
5. **Build → Judge — BLOCK BY BLOCK; the SCRIPTS own the loop state, you obey their exit codes.** Before starting each new block: `node scripts/block-iter.mjs check-phase <phaseDir>` — exit 4 = phase soft-cap: let the in-flight block finish within the grace window, record un-started blocks (`check-phase … --remaining <ids>`), stop. Pick the next unfinished block (dialog/composer-default first, then states; R16), then per block:
   - `node scripts/block-iter.mjs start <phaseDir> <blockId> [--budget strict|balanced|thorough]` (budget from the command's `--budget`, default balanced).
   - Invoke **velt-builder** (maker) ONCE for the block with {the work-list item + its `ruleIds`, the Connect Map slice, token map, chosen layer, the guide-lookup route (`guide-lookup.mjs files --role build --approach <layer> --surface <surface>`), and — on a re-round — the Judge's named regions/delta rows}. The Builder owns the inner patch loop: patch → cheap self-probes → `block-iter.mjs record --diff-count … --hash …`, obeying its exit codes (0 continue · 5 escalate the layer once per `guide/02-decision-tree.md` · 4 STOP — STUCK already written by the controller). It returns at a PASS-candidate (self-probes clean + lint 0 errors + render smoke-test) or when stopped.
   - Invoke **velt-judge** (checker, FRESH context — never the Builder's reasoning or self-probe results) at TWO points only: once after the block's first structural build (gross-structure catch: capture + visual-diff), and at each PASS-candidate (full pipeline: reset/seed/drive → capture → visual-diff `--json-out` → delta/LAYER/CONTRACT/STABILITY probes persisted verbatim → icon identity → `report-block.mjs measure`). The Judge persists every artifact and **never hand-writes `block-report.json`**; an unseedable state is recorded via `report-block.mjs account --disposition BLOCKED --evidence <triage file>`.
   - Run `node scripts/verdict-gate-blocks.mjs --blocks blocks.json --report block-report.json` after each Judge verify. **FAIL** → hand the named diffs back to the Builder (same block, next round; the controller keeps counting). **INCOMPLETE** → a coverage/artifact/audit hole — fix the accounting, never argue with it. Block accounted (PASS / STUCK / BLOCKED / GAP) → advance; gate exit 0 or 4 → step 6. *(In `step` mode: one block-round per invocation, surfacing the Judge's evidence + gate verdict for the transcript.)*
6. **Terminate — decided MECHANICALLY by `verdict-gate-blocks.mjs` exit code, never by you, the Builder, `/goal`, or an agent's say-so.** After each block you run `node scripts/verdict-gate-blocks.mjs --blocks blocks.json --report block-report.json`; it returns `PASS`(0) / `FAIL`(2) / `INCOMPLETE`(3) / `STOPPED`(4). **`INCOMPLETE` — a block not built, a state not driven, or an artifact missing — is NOT done; keep looping (this is what blocks the M5 build-5-of-16-and-stop).** `FAIL` ⇒ keep looping (fix the named diffs). The phase stops when the gate exits **0** (every block PASS, or a verified `BLOCKED`/`GAP` with an evidence note) **or 4** (`STOPPED` — a block is `STUCK` at its bounds, or the 60-min soft-cap listed un-started blocks under `report.phase.remaining`). Do NOT outsource the stop to `/goal`. **You and the Builder can NEVER self-declare "matched"**; **"looks close"/"diminishing returns" is NOT terminal — keep looping** until the gate exits 0 or 4. **Human override (the ONLY thing that overrides the mechanical gate):** if the user explicitly says **"I've checked, it's good for now"**, accept the current state despite a non-clean gate — record it as human-accepted for the named block/phase and stop; absent that explicit acceptance, a FAIL/INCOMPLETE is never "done." **On stop, ALWAYS write the phase handoff** from [`templates/phase-handoff.md`](../templates/phase-handoff.md): the `git diff --stat` of `components/velt/ui-customization/`, the per-block disposition table (PASS/FAIL/STUCK/BLOCKED/GAP/REMAINING), what's uncertain (icon-vision, suspected false-cleans), what could NOT be verified (BLOCKED states), required host changes (R18), exact fix-instruction examples, and a recommendation (say **"phase N complete"** vs fix `<blockId>` first). Then the command may invoke you to write the fuller `velt-customization-report.md` + `sdk-gap-report.md`. **On the user's "phase N complete":** snapshot, then **freeze verified learnings into memory** — `node scripts/memory.mjs promote --dir . --phase <phaseId> --from <learnings.json>` (tokens actually used, mappings that passed, accepted naming, fix-cycle corrections, verified gaps; NEVER failed attempts, tentative assumptions, or env-workarounds) — and mark the phase `user_complete`.

## Cloud / autonomous mode (`--cloud`)
When the command passes `--cloud` (headless: Cursor cloud agent, CI, any no-TTY box), run the **identical** flow with two differences — **never block on a human, never assume a local desktop**. Everything below is a delta on the Sequence above; the Build→Judge loop, escalation ladder, bounds/stuck-detection, and the mechanical `verdict-gate-blocks.mjs` terminator are UNCHANGED.
- **No interactive stops — every HALT becomes a fail-fast exit.** The Approach Gate (Step 3) is satisfied ONLY by `--mode`; if `--mode` is absent, do **not** ask — write `HALTED: --cloud requires --mode` to `progress.log` + the handoff and stop. Likewise a hard preflight ✗ or a blocked-auth condition is written to the handoff and ends the run (non-zero), never an interactive wait. There is **no** manual-login pause in `--cloud`.
- **Design intake is REST regardless of mode** (there is no Figma MCP anywhere); in `--cloud` the token is read from the `FIGMA_TOKEN` env var (no keychain). No token / node won't resolve ⇒ HALT.
- **Preflight browser item changes — verification is no longer desktop-bound:** replace **(5) “`Cursor's native browser tool` connected”** with **a headless Chromium reachable** — `capture-block.mjs` launches (or `--connect`s) `playwright-core`, and the Judge seeds/drives/probes that **same** browser over CDP (reuse it across a block's iterations via `--connect <wsEndpoint>`). Keep **(1) guide**, **(2) Figma token + REST resolves**, **(3) Velt installed**, **(4) app boots + Velt renders** as hard items — the app must boot into an **authed, Velt-rendering** state from env/secrets (item 6 auth is pre-provisioned, not deferred to a pause).
- **Setup MAY run non-foreground** (the heartbeat file already exists via `phase-init.mjs`). Keep appending every sub-step to `progress.log` so the CI/agent log still shows liveness and any fail-fast reason is captured.

## Loop control — OWNED BY `block-iter.mjs` (you never count iterations or keep time yourself)
- The controller owns iterations, wall-clock, plateau detection (no-progress / repeat-hash / oscillation), the single layer-escalation, **auto-writing STUCK** (with evidence), and the phase soft-cap. Budgets: `--budget strict|balanced|thorough`. You cannot mark a block STUCK by hand — only the controller writes it.
- Forced improvement is controller-enforced: a retry whose failing-diff count doesn't strictly drop is no-progress; a repeated/oscillating normalized-diff hash aborts the chain.
- Judge **FAIL** → re-round the Builder with the named `{element, property, spec, rendered}` diffs (budget is generous while the diff count keeps falling — the controller decides when it isn't). Judge **BLOCKED** → fix the environment if you can, else record via `report-block.mjs account --evidence`; never silently pass.
- **GAP** is declared ONLY via `report-block.mjs account --disposition GAP --evidence <F3-exhaustion file>` after the Builder's evidence shows inspect→override→data-driven→full-container exhausted. The gate rejects any STUCK/BLOCKED/GAP whose evidence file doesn't exist — dispositions cannot escape the loop.
- A gate PASS is concluded only over **script-assembled artifacts** (`report-block.mjs` + the gate's artifact audit: PNGs must exist and be fresh, report must match the persisted probe JSONs, hand-written entries are rejected).

## Guardrails
Run in **cwd** (the user's project); touch only `components/velt/ui-customization/` + the `.velt-customize/` phase dir. **Never alter the host app's non-Velt UI or default behavior (R18)** — if a host change is genuinely required, apply it temporarily, verify, **revert it**, and list it in the handoff as a required manual change; never bake it in. Never enter credentials. No deletes / config changes / commits unless asked. **The MANDATORY approach is the one guaranteed user interaction: taken from `--mode` if supplied, else a HALT-and-ask at the Approach Gate (never auto-picked).** (A hard preflight failure halts with a fix — not a question. Manual-auth pause is a safety exception.) Everything else — recognition ambiguities, layer escalations, retries — is autonomous; log it and surface in the handoff. Persist the journal after every step so an interrupted run resumes; phase artifacts are keyed by a stable `phaseId`.
