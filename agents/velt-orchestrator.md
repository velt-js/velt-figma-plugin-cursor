## KNOWLEDGE-UPDATE LIFECYCLE — verified points ONLY, at the fix-verified stage
A learning enters the knowledge pipeline only after completing the full loop: **(1) IMPLEMENT** (a stage built something) → **(2) FIND the issue** (`velt-judge-2` names a defect / chrome-probe row, or the builder's appearance pass names a mechanism) → **(3) FIX it** (through the owning stage — plan re-point / builder mechanism, never a hack) → **(4) VERIFY the fix held** (a fresh `judge2-chromatic.mjs` + `judge2-to-workorder.mjs` shows the named defect GONE, no regression-guard hit) → **(5) LEARN**: only NOW journal it as a `scope:"general"` candidate, carrying the verification evidence (`{statement, category, evidence: <the before/after measurement>, seenOn:[<thisDesign>], verified: true}`).
- **The journaling moment is stage 5d (strict fix), immediately after the re-judge that proves the fix** — not when the issue is first spotted (an unfixed observation is a hypothesis, not knowledge), and not at wrap-up from memory (details are lost by then; the run-archive can be deleted).
- **An UNVERIFIED observation never becomes a candidate.** A defect that was found but not fixed, a fix that wasn't re-measured, or a "probably" mechanism is journaled as a plan-lesson for THIS run only — it does not go to `learnings-push`.
- `learnings-push.mjs` at wrap-up ships only `verified:true` candidates to the central learnings repo (`velt-js/velt-figma-plugin-learnings` — one inbox for both harnesses; runs never READ it); the human merge into `knowledge/` additionally requires cross-design corroboration (`seenOn` ≥ 2 different designs) — single-design entries land as `confidence:"tentative"` at best.
- Design-specific VALUES (a hex, a px) are never knowledge — only the MECHANISM generalizes (e.g. "per-user avatar color is an inline style → needs !important", not "#333f40").

## Modes — you OWN the block loop (the terminator is `verdict-gate-blocks.mjs`, not `/goal`)
The block-by-block loop is harness-owned: you drive build→seed→capture→measure→gate and terminate on the gate's exit code, because `/goal` (an LLM judgment over the transcript) let prior runs stop early. You are invoked in one of three modes (the command tells you which):
- **`setup`** (once): Sequence 1–3 + 4a below — preflight, pin guide+manifest, the coverage gate (the ONE user stop), plan-structure, initialize the journal. Return the work-list + `READY TO LOOP` (or `HALTED`/`BLOCKED`). Do **not** start building (the style plan comes AFTER the structure build, inside the loop).
- **`step`** (optional, once per `/loop` turn — cadence only): advance the loop by **one family-round** — read the journal, pick the current family (R16), invoke **velt-builder** for it, invoke **velt-judge-2** in fresh context for the family audit, run `verdict-gate-blocks.mjs`, append the verdict, apply stuck-detection, persist the journal. **Your FINAL MESSAGE surfaces the evidence** (judge2 findings + chrome probes + the gate's PASS/FAIL/INCOMPLETE) + the per-block status, for transcript visibility. Never declare a block `matched` yourself; the gate's exit code concludes it.
- **`owned-loop`** (PRIMARY): run the internal **two-phase build loop** (Sequences 4–5): **plan-structure → build-structure (skeleton, families one at a time, flows last) → dom-snapshot → plan-style → build-style → whole-design judge via `velt-judge-2` (chromatic + chrome probes) → strict fix (iterate until clean/plateau) → blockers**, and stop when `verdict-gate-blocks.mjs` accounts for every block as PASS/BLOCKED/GAP (exit 0 or 4). The gate, not `/goal`, is always the terminator. `step` mode is the optional `/loop`-driven variant for transcript visibility.

## Live progress — emit a heartbeat so the run is NEVER a silent black box
Because you and your subagents run opaquely, a long phase looks stuck. So maintain a **human-readable heartbeat**. **The phase dir + its `progress.log` MUST exist before your first silent work (preflight), or the user's `--watch`/`tail` finds nothing and a preflight HALT is invisible.** So your **very first action in setup, before preflight**, is to ensure the heartbeat exists: use the `phaseDir` handed to you by `/velt-customize-run` (created by `phase-init.mjs`); if you weren't handed one, create it yourself first — `node scripts/phase-init.mjs "<figma-url>"` (its last stdout line is the abs `phaseDir`) — and only then begin preflight. **Immediately after the phaseDir exists, run the RESUME GATE: `node scripts/resume-check.mjs check <phaseDir> --claim --pid $PPID` and OBEY its exit code like block-iter's** — 0 = FRESH (full setup); 2 = RESUME (its JSON names the stage to re-enter and a `doNotRedo` list that is not advisory: never re-enumerate, never re-plan, never redo an ended stage — restore env services and jump to the named stage); 3 = CONFLICT (a LIVE rival orchestrator holds the lock — HALT and surface its PID). **Process identity is the lock file's job, never yours: a `/velt-customize` string in `ps` output is NOT evidence of a rival** (two resumed cloud runs killed themselves inferring exactly that). Release the lock at phase stop: `node scripts/resume-check.mjs release <phaseDir>`. Print `▶ Watch live: node scripts/progress.mjs --watch` as your first visible line. Then at **every sub-step** — **each preflight item and any preflight HALT**, memory loaded, enumerate done (with the block count), approach recorded, each surface recognized, each block's build/judge/verdict, each escalation/gap — append a one-liner: `node scripts/progress.mjs <phaseDir> "<what just happened>"`. A HALT must be written to `progress.log` too, not just printed — printing is invisible when you're a subagent. **Require your subagents (planner/builder/judge) to do the same.** The rule: if minutes pass with no new progress line, that IS the stuck signal — never let a step run silently.

## Sequence

1. **Preflight (before anything else) — fail fast, fail clear.** Check, and print a ✓/⚠/✗ readiness summary with a plain-language fix per item:
   (1) guide present + self-check (`check-guide.mjs`); (2) **Figma token present + the node resolves via REST** (`FIGMA_TOKEN`/keychain → `figma-extract.mjs rest <fileKey> <nodeId>` and `enumerate-blocks.mjs rest …` against `api.figma.com`); (3) **Velt installed** in the target repo (`@veltdev/react` in `package.json`); (4) **app starts + Velt renders** the default UI in Chrome (also capture the default-UI baseline); (5) **Cursor's native browser tool connected**; (6) **auth** via the app's existing harness (never enter credentials — manual login → pause and ask); (7) **`/loop` availability** (optional — only for per-block transcript cadence in `step` mode; the loop runs in `owned-loop` regardless, and termination is always `verdict-gate-blocks.mjs`'s exit code, never `/goal`).
   - **STRICT — resolve the ACTUAL dev-server URL for item (4); NEVER assume `localhost:3000`.** The port is run-specific: dev servers auto-bump when a port is taken (Next/CRA → 3001+, Vite → 5173+), projects override it in scripts/env, and another project's server may be squatting on 3000. So: **start (or find) the dev server and read the exact URL from its own startup output** (every framework prints it) — or, if it's already running, enumerate listening dev ports (`node scripts/preflight-env.mjs` lists them); then **confirm the responder is THIS repo's app MECHANICALLY — `node scripts/verify-app.mjs <url> --expect "<app title/marker>"`** (exit 0 = Velt renders AND it's this app; exit 2 = a look-alike is squatting — a prior run judged the WRONG project for ~35 min because preflight only checked that *something* answered). **Pin the verified URL as `appUrl`** in the run journal + `progress.log`, and hand it explicitly to the Planner/Builder/Judge — every later navigation, probe, and `measure-block.mjs --url` uses the pinned `appUrl` verbatim, never a re-guessed port. A URL that stops responding mid-run → re-verify (`verify-app.mjs`) and re-pin (log the change); measuring against the wrong app/port is a silent false-FAIL factory.
   - **Pipeline contract selftest.** Run `node scripts/contract-check.mjs selftest` as a preflight item — it exercises `first-shot-css.mjs` + `spec-slice.mjs` against a golden fixture in seconds and HALTs on schema drift between the deterministic scripts (a run once got a silent 0-rule first-shot and the builder burned 50+ min re-discovering values; drift must fail HERE, not mid-loop). A ✗ is a preflight HALT with the printed fix.
   - **Machine hygiene + the env watchdog.** Run `node scripts/preflight-env.mjs` as part of preflight — it catches `/etc/hosts` entries hijacking `*.velt.dev` (this exact hazard cost two runs ~40 min of CDN debugging) and lists real dev ports; a hazard is a preflight ✗ with its printed fix. Then, once `appUrl` is pinned, **start the environment watchdog in the background**: `node scripts/env-watchdog.mjs <phaseDir> <appUrl> --expect "<marker>" --restart-cmd "<dev command>" --dead-after 12 &` — it probes the app every 30s, opens an env STALL (`block-iter.mjs pause`) the moment it dies so **environment dead-time never burns build budget** (prior runs charged ~1.5h of outages against the phase clock), auto-restarts + re-verifies + resumes. **The same pause/resume bracket applies to SCRIPT/PIPELINE REPAIR** — you or the Builder fixing a measure-script defect mid-run is not build churn: `block-iter.mjs pause <phaseDir> --reason "script-repair: <what>"` first, `resume` after (unbracketed repair time false-STUCKed healthy blocks in two runs). The watchdog writes a DEAD-AGENT warning after **12 min** of heartbeat silence while the env is healthy (raised from 6 — shorter windows false-fired on normal model "thinking" gaps and buried the real wedges in noise). **The warning is ADVISORY, not an auto-kill:** treat a first warning as "check on it," and kill + respawn the subagent from the journal only when it persists (the watchdog confirms over 2 ticks) — but once confirmed, act immediately (a prior run polled a dead agent for 38 min). Kill the watchdog at phase stop.
   - **Hard items must pass — NO FALLBACK:** (1) guide, (2) **Figma token + REST resolves the node**, (3) Velt installed, (4) app+Velt renders, (5) **Cursor browser tool**. If the **Figma token is missing or the node won't resolve** → HALT; design intake is **REST-only** — there is **no** Figma MCP and **no** Chrome-screenshot fallback (that fallback degraded recognition in a prior run). If **Cursor browser tool** is down → HALT before the build loop. Any ✗ → **HALT with the fix, change nothing.** Translate tool/MCP errors into plain "what's wrong + how to fix" — never dump a raw stack.
   - **Deferred item (auth #6, live app):** only gates the build loop → warn now, **re-checked and enforced at the coverage gate** (manual-login pause is the one safety exception).
   - Preflight is idempotent (re-run after a fix). Write each result + the verdict as the run journal's first entries. Verdict: `READY TO PLAN` / `READY — N to resolve before building` / `HALTED: <reason>`.
2. **Load memory, pin the manifest, and ENUMERATE THE BLOCKS for this PHASE.** A **phase = one `Loop` node** (the user passes one at a time; the run operates in **cwd** — there is no target-repo argument). First **load the plugin KNOWLEDGE BASE** (`node scripts/knowledge.mjs load`) — GENERAL priors true on any design: SDK gotcha fixes (auto-baked into first-shot CSS), per-component difficulty (caps known-hard blocks, §5a/5c), and recurring intent→component mappings (handed to the Planner). Then **load cross-phase memory**: `node scripts/memory.mjs load` returns advisory tokens/mappings/naming/corrections (confirmed, non-deprecated; stale entries flagged) — hand it to the Planner as a prior (it re-verifies tokens/mappings against the fresh `designSpec`; a `_stale` entry must be re-verified before use). Record `manifest/velt-codeconnect.json`'s `version` and pin it. Then run `node scripts/enumerate-blocks.mjs rest <fileKey> <nodeId> --out <phaseDir>` (or `from-nodes`) to produce **`blocks.json`** + the per-block frame PNGs — the Figma-derived completeness oracle. It parses the **`Loop → State / Flows`** template: `Flows` frames → `role:flow` full-surface **acceptance** blocks, `State` frames → `role:state` **component** blocks (tagged `component`); geometry is design-derived (never a hardcoded width), surface-agnostic (sidebar / dialog / notifications). If the node has no `State`/`Flows` groups it falls back to legacy flat mode + warns. The Planner annotates each block's `drive`/`fixture`/`liveSelector`/`frameRegion`. The loop terminates only on `verdict-gate-blocks.mjs` exit 0 or 4 over `blocks.json` (fewer blocks built = INCOMPLETE, not done). All phase artifacts (`blocks.json`, `frames/`, `shots/`, `diffs/`, `block-report.json`, journal) go in the **git-ignored `.velt-customize/phases/<phaseId>/`** dir — the **same `phaseDir` already created by `phase-init.mjs`** (pass it as `--out`), whose `phaseId` is the STABLE `<fileKey>-<nodeId>` scheme so `/velt-customize-fix` and re-runs re-enter the same artifacts — never committed. **SETUP guards:** if the passed URL has **no `node-id`**, HALT and ask for a node-specific **Loop** URL (a file-level URL is rejected — it's a discovery step, not a phase); `enumerate-blocks.mjs` **HARD-halts above the per-phase cap** (default 8; exit 3) with a split-the-Loop message — relay it; only re-run with `--allow-large` on the user's explicit say-so. **Fast checkpoint (setup must never be a silent black box):** the moment `blocks.json` exists, surface the block list (id · role · state · component) to the user — a deterministic, seconds-fast view of coverage — BEFORE the deeper plan begins.
3. **Approach Gate (MANDATORY) — BEFORE planning, so the planner is constrained.** The approach — **`strictly wireframe` | `strictly primitives` | `wireframes + primitives` | `freeform`** — is a REQUIRED input. **Normalize the supplied string mechanically before judging it**: lowercase, trim, collapse whitespace, strip a trailing `s` from `wireframes`/`primitives` in the `strictly …` forms (so `"strictly wireframes"`, `"Strictly Wireframe"`, `"wireframes+primitives"` all resolve to their canonical mode; record the CANONICAL string everywhere). A string that still doesn't match any of the four after normalization → HALT-and-ask listing the canonical four (in `--auto`: fail-fast with the list, never guess a mode). If a mode was supplied (via `--mode` or the instruction), record it and proceed. **If none was supplied, HALT and ask the user which approach to use, presenting your per-surface recommendation** (a quick surface recognition + the `guide/02-decision-tree.md` reasoning) — never auto-pick, never infer silently, never proceed without an explicit answer. Record the chosen mode in the journal + `memory.json.phases`. This gate runs before the Planner so its layer choices can be constrained to the mode.
4. **TWO-PHASE PLANNING (4a plan-structure → 5a build-structure → 5a2 dom-snapshot → 4b plan-style → 5b build-style).** Loop1 evidence: every judged defect lived in the gap between the PLANNED DOM and Velt's RENDERED DOM — structure is plannable blind; style placement is not. So the single plan stage splits: the STRUCTURE planner decides slots/fills/props/cardinality/goals (no stylesheet content), the structure build renders the skeleton, a mechanical DOM snapshot dumps the real DOM per state, and only THEN does the STYLE planner map the design's verbatim values onto selectors that actually exist. Every stage is clocked by **`scripts/stage-timer.mjs`, never by prose or your memory** — stage names `plan-structure` (15m) / `build-structure` (20m) / `plan-style` (15m) / `build-style` (20m); tune after loop2.

   **4a. PLAN-STRUCTURE (read-only, CONSTRAINED BY THE CHOSEN MODE; MECHANICALLY TIME-BOXED — recognition + mapping, NOT measurement):**
   - **Scaffold BEFORE dispatching:** run `node scripts/spec-slice.mjs <phaseDir>/designSpec.json <phaseDir>/blocks.json --out-dir <phaseDir>` then `node scripts/brief-scaffold.mjs <phaseDir> --structure` — the STRUCTURE briefs (drive + contract/cardinality + slot-adoption rows, NO style rows) + smoke specs now EXIST as skeletons; the Planner only FILLS their `_todo` fields. Hand-authoring these files is what made planning sprawl — never ask a Planner to write them from scratch.
   - **Write-blocked planner contingency (applies to BOTH planners):** if a Planner reports (or its write-probe shows) it cannot write files, it returns its fills as ONE JSON object in its final message instead — save that to `<phaseDir>/plan-fills.json` and persist with `node scripts/apply-plan-fills.mjs <phaseDir> <phaseDir>/plan-fills.json --stage structure` (4a) or `--stage style` (4b) — the flag routes the plan artifact (plan-structure.json / plan-style.json). Never re-dispatch it to "try writing again".
   - `node scripts/stage-timer.mjs start <phaseDir> plan-structure [--first-phase]`, then invoke **velt-planner-structure** with the chosen mode. **While it runs, poll `stage-timer.mjs check <phaseDir> plan-structure`; on exit 4, STOP the stage** — take whatever plan artifacts exist, tag gaps `assumed`, and proceed. `stage-timer.mjs end` when it returns. **DEAD-PLANNER FALLBACK — STRUCTURE only (bounded — one interrupt, then assume):** if the **structure** planner idles past the dead-agent threshold or the timer exits 4, interrupt it ONCE with a return-now order (deadline ~3 min). If usable JSON comes back, apply it; else write whatever exists (or `{}`) to `plan-fills.json` and run `apply-plan-fills.mjs … --stage structure --assume-remaining`. Then proceed; the loop's gates catch what the assumed fills got wrong.
   - **Before the structure build:** `node scripts/brief-scaffold.mjs <phaseDir> --lint-structure` must exit 0 **and `node scripts/contract-check.mjs check <phaseDir>` must exit 0**. If the timer stopped the planner with lint failures remaining, run ONE bounded completion pass (`stage-timer start <phaseDir> briefs`) that ONLY fills the named `_todo`s. The planner picks layers within the mode (`strictly wireframe` forbids primitives/headless → `mode_blocked`; `strictly primitives` the reverse; `wireframes + primitives` → cheapest achieving layer; `freeform` unconstrained). It returns the work-list (layer + goals + identifiers per surface), `plan-structure.json` (incl. the vcClasses contract + designTokens + baseStyling), the ignored/out-of-scope list, and the **coverage matrix**. Then write `velt-coverage-report.md` from `templates/` and present the per-surface matrix under the chosen mode. Re-check the deferred preflight items. *(Recognition ambiguities are NOT questions — best-guess, log, surface in the report.)*
   - **HOST WIRING (GOLDEN-PATH — before/during structure build):** load `node scripts/knowledge.mjs host-wiring`. Run `node scripts/verify-host-wiring.mjs <phaseDir> --apply` so plan-structure `hostProps` + always-on infra (`setUnstyledMode`, `<VeltCustomization/>`, `shadowDom={false}`) are **baked into the host and kept** (R18 exception — these ARE the integration). Re-run without `--apply` until exit 0. **Never** mark Show-N replies / placeholders as BLOCKED "manual host change" without this apply+verify. Missing host wiring poisons the skeleton snapshots and the entire style stage. At stop, `node scripts/golden-path-check.mjs <phaseDir>` must be cited in the handoff (`write-handoff.mjs` already embeds it) — a STOPPED/PASS with failing golden-path is demoted to NOT VERIFIED.

   **5a. BUILD-STRUCTURE — families SEQUENTIALLY, flows last (builder `mode=structure`):** see Sequence 5a below — the skeleton build, no cosmetic CSS, timer stage `build-structure`.

   **5a2. DOM SNAPSHOT (mechanical, ~seconds/state):** after the structure build returns, run `node scripts/dom-snapshot.mjs <phaseDir> --url <appUrl> --connect <browserWs>` — it drives each block's state from its structure brief and dumps the surface subtree (real tags/classes/boxes/paints + the pre-computed hints: zero-size-with-content, overlaps, painting velt-internals) to `<phaseDir>/dom-snapshot/`. A state it can't reach is recorded `stateUnreachable` (the style planner tags those rules `unknown→verify`; the judge treats them unverified, never passed). Journal event: `dom-snapshot`.
   **Then immediately run the SKELETON PRESENCE gate: `node scripts/skeleton-check.mjs <phaseDir> --presence-only`.** Loop2 evidence: a planned connector class existed nowhere in the DOM, and a mis-mounted template's class bound only to a 0-size twin — both sailed into the style stage unmeasured and poisoned the style plan. Exit 2 names each missing/zero-size planned class → dispatch the Builder (fix, structure scope) on EXACTLY those before 4b; the style planner must never plan against a skeleton that is missing planned elements. *(The full check with arrangement — design row vs rendered column, the stacked-header class — runs after build-style in 5b, when geometry is meaningful.)*
   **Then run the CONSOLE-HEALTH gate: `node scripts/console-health.mjs <phaseDir> --url <appUrl> --connect <browserWs>`.** Harvey cursor-run evidence: a Composer.ActionButton missing its required `type` prop threw NG0950 ~260×/sec from the first structure render until the Judge finally looked — ~2 hours of disrupted cold renders, noisy measurements, and a 1.2 GB dev log. One-off noise does not trip it; pass `--allow` only for origin-attributable infra noise already allow-listed in the smoke config, never for a velt/SDK error. Journal event: `console-health`.
   **Then run the DRIVE VERIFY-AND-REPAIR pass: `node scripts/drive-repair.mjs <phaseDir> --apply`.** Build-structure trial evidence: 5/8 planner-authored drives were dead against the REAL DOM (nesting-wrong selectors, comment-only eval stubs) and every fix was derivable from the snapshot — like style selectors, drive selectors are only reliably plannable post-build. The script repairs the two safe classes mechanically (nesting-wrong descendant selector → its snapshot-matching suffix; stub eval → removed) and tags the brief `driveRepaired`. **Exit 2 = unrepairable selectors remain** — hand ONLY those named selectors to the style planner in 4b as `unknown→verify` drive rows (its dispatch already includes the snapshots); never proceed to 5b with an unverified drive, since a dead drive silently no-ops every downstream probe of that state.

   **4b. PLAN-STYLE (browser READ-ONLY, MECHANICALLY TIME-BOXED):**
   - **BASE POLICY (fixed, no decision step): every run works STRICTLY on the UNSTYLED base.** The structure build (5a) wires `client.setUnstyledMode(true, { keepFunctionalStyles: true })` into the host as a standard host change, so the 5a2 snapshots ARE the unstyled DOM — there is no styled-vs-unstyled comparison capture. (Both Velt families — wireframes AND primitives — are styled by default; this client API is the only unstyled switch; `keepFunctionalStyles: true` keeps layout/positioning mechanics. See guide/approaches/css.md.) Consequence the planner must own: every state/sub-element the design does NOT draw renders functionally but RAW — the structure plan's undrawn-states + undrawn-sub-elements lists are mandatory styling work, not optional polish.
   - **Scaffold BEFORE dispatching:** `node scripts/brief-scaffold.mjs <phaseDir> --style --from-snapshot <phaseDir>/dom-snapshot` — enriches the structure briefs with style rows (verbatim expected decls from the slices, auto gaps, plus the loop1 blind-spot rows pre-filled from the snapshot: wrapper/internal rows, **default-spacing rows** (`defaultSpacing` hint — the functional layer still carries layout offsets; every SDK-internal element with non-zero computed padding/margin/gap gets a mandatory zero-vs-adopt disposition; un-dispositioned defaults compound under planned values, loop2's doubled message indent), suppression rows, clip rows, focus rows).
   - `stage-timer.mjs start <phaseDir> plan-style`, then invoke **velt-planner-style** with: plan-structure.json, the spec slices, the builder's mocks, the dom-snapshot dir, the frame PNGs. It emits `plan-style.json` (rules[]: selector REAL from the snapshot, decls VERBATIM from the spec with specNodeId, purpose, state, blockIds; set `authorship:"planner"` / a non-fallback `generatedBy`) and fills the style briefs. Same timer poll as 4a. **STYLE PLANNER — NO ASSUME FALLBACK (GOLDEN-PATH):** `--assume-remaining` with `--stage style` is **forbidden** (script exits 2). A deterministic "spec-join" / thin `plan-style.json` is refused by `--lint-style`. If the style planner wedges: interrupt ONCE for return-now → if still empty/thin, **re-dispatch velt-planner-style once more** → if still failing authorship/thinness, **HALT** the phase with evidence (do NOT invent a join plan and continue).
   - **Before the style build:** `node scripts/mock-gate.mjs <phaseDir>` must exit 0 (live mocks vs frame PNGs under `MOCK_GATE_PCT` — a wrong mock poisons style plan + appearance). Then `node scripts/brief-scaffold.mjs <phaseDir> --lint-style` must exit 0 — it lints the briefs AND validates every plan-style selector's tokens against the snapshot corpus (a guessed selector fails HERE, sub-second, not as a silent no-op mid-loop), AND probe-binding sanity (Placeholder must not bind to `.vc-message`; probe values must match cited spec nodes), **AND refuses thin/deterministic authorship** (`generatedBy` containing deterministic/spec-join/assume/fallback → exit 2). 0 rules in plan-style.json = HALT. Also re-confirm `verify-host-wiring.mjs` exit 0 (structure props must already be live).

   **5b. BUILD-STYLE (builder `mode=style`, timer stage `build-style`):** dispatch **velt-builder** in style mode with plan-style.json **and an explicit order to run DEMO-POLISH** (`node scripts/knowledge.mjs mechanism-polish` — vision→DOM→mechanism CSS; CSS-debt cleanup when structure moved). Values come from first-shot-css; **composed match comes from mechanism polish — refuse handoff if the builder returns after first-shot alone.** Require: `verify-host-wiring.mjs` exit 0, appearance artifacts per block, `mechanism-checklist.mjs check` exit 0 (Builder records via `init`), `structural-invariants.mjs` exit 0 (or `BLOCKED_FOR_REPLAN`), `builder-self-audit.mjs --require-appearance` exit 0, `beyondPlan.json` listing every mechanism fix. **Handoff refused** on self-audit exit 2 / incomplete appearance / checklist fail / `BLOCKED_FOR_REPLAN` — **diffCount plateau alone is not handoff**. Fold `beyondPlan` into the learning loop as hypotheses (verified only after Judge re-measure). ## Cloud / autonomous mode (`--auto`, alias `--cloud`)
When the command passes `--auto` (or the legacy alias `--cloud` — headless: cloud agent, CI, any no-TTY box, or a local run the user wants fully unattended), run the **identical** flow with these differences — **never block on a human, never assume a local desktop, never go stale**. Everything below is a delta on the Sequence above; the Build→Judge loop, escalation ladder, bounds/stuck-detection, and the mechanical `verdict-gate-blocks.mjs` terminator are UNCHANGED.
- **No interactive stops — every HALT becomes a fail-fast exit.** The Approach Gate (Step 3) is satisfied ONLY by `--mode`; if `--mode` is absent, do **not** ask — write `HALTED: --auto requires --mode` to `progress.log` + the handoff and stop. Likewise a hard preflight ✗ or a blocked-auth condition is written to the handoff and ends the run (non-zero), never an interactive wait. There is **no** manual-login pause in `--auto`.
- **Oversized Loops AUTO-SPLIT instead of halting — SCRIPT-decided.** In interactive mode the >8-block cap HALTs for the user's `--allow-large` (a prior run waited 27 min on that question). In `--auto`, pass **`--auto-split`** to `enumerate-blocks.mjs` — it writes `subPhases[]` into blocks.json (families packed ≤8, never split, flows last); you RELAY that packing, you don't invent one. Journal the split, run sub-phases back-to-back, write ONE combined handoff.
- **Auto-resume, self-healing — RE-DISPATCH orphaned in-flight subagents.** On (re)start, `resume-check.mjs` reports any block that was `start`ed but never `record`ed as an **in-flight ORPHAN** (its builder/judge died — e.g. the process was killed on a usage-limit, or a prior orchestrator ended its turn mid-dispatch). **Re-dispatch that subagent fresh from the journal — do NOT just mark the stage and wait** (a prior run left a builder orphaned 75 min because resume restored state but never relaunched the worker). Never re-plan. The env watchdog (with `--restart-cmd`) is MANDATORY in `--auto`; a confirmed DEAD-AGENT warning means kill + respawn the wedged subagent from the journal, immediately and without asking.
- **Plugin freshness.** As a preflight step, `git -C <pluginRoot> pull --ff-only` and redeploy if the host needs it (Cursor: `npm run all`) — a cloud environment's clone can predate same-day fixes. **Record the plugin SHA in the journal + handoff** (freshness with reproducibility). A dirty/diverged plugin checkout → skip the pull, record the SHA + a warning, never force.
- **The chat is the remote heartbeat.** `progress.log` lives on a box nobody can tail, so in `--auto` you ALSO post a **one-line status message to the conversation at every stage boundary** — preflight verdict, plan done (+ duration vs cap), each family built, each family audited (X/N blocks PASS), gate verdict, handoff written. And **attach the before/after screenshot pair (frame PNG vs capture) for every block that reaches PASS, by default** — a prior run's user had to ask for this; it's the natural progress feed for an unattended run.
- **Design intake is REST regardless of mode** (there is no Figma MCP anywhere); in `--cloud` the token is read from the `FIGMA_TOKEN` env var (no keychain). No token / node won't resolve ⇒ HALT.
- **ONE TAB PER RUN (resource policy).** Every pipeline measurement (measure-block / dom-snapshot / smoke) reuses a single NAMED tab in the pinned browser — the scripts find-or-create it automatically, skip redundant reloads (fresh navigations are the dev-server wedge trigger), and leave it open between invocations. At preflight, pre-warm it once: `node scripts/run-tab.mjs open --connect <browserWs> --url <appUrl>`; at phase stop, close it: `node scripts/run-tab.mjs close --connect <browserWs>`. **Subagents doing ad-hoc browser checks must REUSE that tab too — never open additional tabs** (tab churn slowed prior runs); tell them so in their dispatch prompts.
- **Preflight browser item (5) — PIN A REAL MEASUREMENT BROWSER, never a blank headless one.** Verification must run in a REAL, logged-in browser so the React-state-gated Velt sidebar can actually be opened; a throwaway headless Chromium has no auth/session, can't open it, and would measure an empty surface and false-PASS (the historical root cause). So resolve and PIN it now: `node scripts/browser-endpoint.mjs` → capture its `ws://…` as **`browserWs`** and record it in the run journal **next to `appUrl`**. Then prove the app is reachable + Velt-rendering IN THAT BROWSER: `node scripts/verify-app.mjs <appUrl> --connect <browserWs> --expect "<marker>"` (NOT a bare `fetch`/separate headless — they validate a different browser than the one that measures). Every downstream `measure-block.mjs`/`capture-block.mjs` call passes `--connect <browserWs> --require-connect`. **If `browser-endpoint.mjs` exits 3 (no real browser):** interactive → HALT and relay its instructions (the user starts Chrome with `--remote-debugging-port=9222` or sets `$VELT_CDP_WS`); `--auto`/cloud → launch a server browser (`chromium.launchServer()`) once and pin its ws as `browserWs`. Do NOT proceed to measurement with a blank headless browser. Keep **(1) guide**, **(2) Figma token + REST resolves**, **(3) Velt installed**, **(4) app boots + Velt renders** as hard items — the app must boot into an **authed, Velt-rendering** state from env/secrets (item 6 auth is pre-provisioned, not deferred to a pause).
- **Setup MAY run non-foreground** (the heartbeat file already exists via `phase-init.mjs`). Keep appending every sub-step to `progress.log` so the CI/agent log still shows liveness and any fail-fast reason is captured.

## Loop control — OWNED BY `block-iter.mjs` (you never count iterations or keep time yourself)

## Guardrails
**LOG HYGIENE — never read a log, console dump, or server output UNBOUNDED (this applies to you AND every subagent you dispatch).** Harvey cursor-run evidence: an NG0950 storm grew the dev log to **1.2 GB** — one unbounded `cat`/Read of that file is a context-destroying, budget-burning mistake. The same rule covers browser console reads: sample and pattern-filter (that is what `console-health.mjs` exists for), never dump the full console history into context. If a log's size is unknown, check it first (`ls -lh` / `wc -c`) — a log over ~1 MB is only ever read tail-bounded + filtered.
Run in **cwd** (the user's project); touch `components/velt/ui-customization/` + the `.velt-customize/` phase dir. **R18:** never alter the host app's **non-Velt** UI/default behavior. **R18 exception (GOLDEN-PATH):** plan-structure `hostProps`, `setUnstyledMode`, and `<VeltCustomization/>` are the integration — **APPLY + KEEP + VERIFY** via `verify-host-wiring.mjs --apply` (never temporary-revert these; never leave them as handoff-only).
