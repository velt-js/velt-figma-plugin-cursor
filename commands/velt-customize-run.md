# /velt-customize-run

Run the velt-customize flow on the Figma **Loop** and the **live app page** at **$ARGUMENTS**, **in the current project** (cwd — there is no separate target-repo argument).

**Two required inputs (parse both from `$ARGUMENTS`):**
1. `<figma-loop-node-url>` — the Figma **Loop** node (must have a `node-id`).
2. `<app-url>` — the **exact page URL where Velt comments are mounted** (e.g. `http://localhost:3000/inline-comments?documentId=my-run-1`). **This is now required so the run never spends time discovering which page the feature lives on** — preflight *verifies* this URL (does Velt render here?) instead of hunting for it. Include a **run-unique `documentId`** in the query string for isolation (so concurrent runs, or a re-run, never pollute each other's comment data). If only one URL is given, HALT and ask for the app page URL (an allowed blocking question). *(Legacy: if `<app-url>` is truly unavailable, the orchestrator falls back to discovery — but that path is slower and warned.)*

You are the entry point. A **phase = one `Loop` node**. The flow is **TWO-PHASE**: **plan-structure → structure build (skeleton, no cosmetic CSS) → mechanical DOM snapshot → plan-style (against the RENDERED DOM) → style build → whole-design Judge → strict fix (iterate each defect until it measures clean or genuinely plateaus) → blockers list** (see the Loop template in [`velt-operating-brief`](../skills/velt-operating-brief/SKILL.md) + `guide/`): its frames are enumerated into `blocks.json` (the completeness oracle — `Flows`→full-surface blocks, `State`→component blocks, grouped into `families[]`); the structure builder mounts the wireframe skeleton per family (one at a time, flows last), `dom-snapshot.mjs` dumps the real DOM per state, the style planner maps the design's verbatim values onto snapshot-real selectors (`plan-style.json`), the style builder applies it verbatim, the **Judge audits the whole design once** (pixels **plus** scroll/click/hover interaction **plus** the snapshot probes: unexpected-paint, overlap, clip-visibility, driven focus), then each named defect is **iterated until it measures clean (pixel-match) or genuinely plateaus** (the STRICT polish behavior — up to the `--budget` cap: strict 6 / balanced 8 / thorough 12); only a truly-plateaued defect is recorded on the **blockers list**. Termination is **mechanical** on `verdict-gate-blocks.mjs`'s exit code, never `/goal`. The `velt-orchestrator` owns the loop in **owned-loop mode**; `/loop` is optional cadence only. The flow is:

### Watch it live — YOU, the entry point, MAKE THE HEARTBEAT EXIST, THEN print the watch command NOW
Subagent output doesn't stream into this view, so the run writes a **heartbeat log** instead. The catch: a `tail` is useless until the file exists on disk, and the orchestrator doesn't reach its first on-disk write until *after* preflight — so for the whole preflight window (and forever, if preflight HALTs) there's nothing to tail. **Close that window first:** run `node <plugin>/scripts/phase-init.mjs "$ARGUMENTS"` **before you dispatch the orchestrator**. It derives the stable `phaseId`, creates `.velt-customize/phases/<phaseId>/progress.log` with a first line, and prints the absolute `phaseDir` on its last stdout line — **pass that `phaseDir` to the orchestrator** so preflight items + any HALT stream there from second zero. Then print this to the user and tell them to run it in a **second terminal**:
```
node <plugin>/scripts/progress.mjs --watch        # zsh-safe (tail -F); auto-resolves the newest phase
```
Steady new lines = working; a multi-minute gap = genuinely stuck (safe to interrupt). Reliable liveness regardless of heartbeat compliance: `node <plugin>/scripts/progress.mjs --activity`. **Avoid the raw glob `tail -f .velt-customize/phases/*/progress.log`** — under zsh (default `nomatch`) it errors `no matches found` the instant the file isn't there yet, which is exactly the startup window.

Beyond the live heartbeat, the run also **records itself for replay automatically** (every stage, every measurement, every fix iteration — with its screenshot and judge output, preserved per iteration under `<phaseDir>/obs/`). After (or during) the run, `/velt-customize-replay` opens the session-replay player to pinpoint exactly where things drifted; `write-handoff.mjs` prints the player path at the end of every run.

### 1. Setup (once) — invoke `velt-orchestrator` in **setup mode**, in the FOREGROUND
**Do NOT run setup as a background subagent.** Setup is interactive — it can HALT-and-ask on a preflight failure and it *always* stops at the Approach Gate for the user's per-surface choice; a background agent can neither ask those questions nor stream its output (including the `▶ Watch live` line), so backgrounding setup reproduces the silent-black-box failure this design exists to kill. (Only the later **owned-loop** may optionally be backgrounded, and only because the heartbeat file already exists by then.) There is also no lockfile, so "setup is already running" is only your own memory of dispatching — never assume a prior background agent is still alive; check `.velt-customize/phases/*/progress.log` (or `--activity`) instead.

Pass it: the pre-created **`phaseDir`** (from `phase-init.mjs` above — so its first heartbeat lands in the file the user is already tailing), the Figma Loop node/URL (from `$ARGUMENTS`; if absent, ask — an allowed blocking question), **the `<app-url>` (from `$ARGUMENTS`; if absent, ask — the run needs the exact page where Velt renders)**, the target = **cwd**, the feature scope (default: comments + notifications), and the **approach** (see the gate below). **Preflight VERIFIES the given `<app-url>` (`verify-app.mjs <app-url> --expect "<marker>"`) and pins it as `appUrl` — it does NOT discover/guess a page.** If the given URL doesn't render Velt, that's a preflight HALT with the reason (fix the URL and re-run), not a fallback to hunting other ports/pages. In setup mode it: runs **preflight** (HALT on any hard ✗); **enforces the Approach Gate** (below); **loads cross-phase memory** (`node scripts/memory.mjs load` — advisory tokens/mappings/naming/corrections, re-verified against fresh extraction, stale entries flagged); pins the manifest; runs the **planner** (recognize surfaces, pick layers within the chosen approach, synthesize goals + the Connect Map); enumerates the Loop (`enumerate-blocks.mjs` → `Loop → State/Flows` blocks — **rejecting a URL with no `node-id`** and **warning if it yields more than ~8 blocks**); presents the **per-surface coverage matrix**; and **initializes the phase journal**. It returns the work-list + "ready to loop" (or `HALTED`/`BLOCKED`). Planning is **mechanically clocked** (`scripts/stage-timer.mjs` — the orchestrator stops a sprawling plan stage and proceeds with a partial, `assumed`-tagged plan) and briefs are **scaffolded, not authored** (`scripts/brief-scaffold.mjs`; its `--lint` must pass before the loop).

### Approach Gate (MANDATORY — never skipped)
The approach is a required input every run: **`strictly wireframe` | `strictly primitives` | `wireframes + primitives` | `freeform`**. It is supplied via `--mode` or stated in the instruction, and is **normalized mechanically** (case/whitespace/plural-insensitive — `"strictly wireframes"` resolves to `strictly wireframe`; record the canonical string); a string that still matches none of the four → HALT listing them (fail-fast in `--auto`). **If none is given, HALT and ask the user which approach to use, presenting your own per-surface recommendation with the reasoning from `guide/02-decision-tree.md`.** Never auto-pick, never infer silently, never proceed without an explicit answer. Record the chosen mode in the journal + `memory.json`. (`strictly primitives` marks a piece `mode_blocked` rather than silently inserting a wireframe.)

### `--auto` (fully autonomous — headless cloud/CI or a local unattended run; legacy alias: `--cloud`)
Pass `--auto` to run **unattended**: no foreground, no questions, no desktop assumptions, **no going stale** — the env watchdog (with `--restart-cmd`) is mandatory, a dead/wedged subagent is respawned from the journal, an in-flight phase auto-resumes on restart, and an oversized Loop **auto-splits by family** into ≤8-block sub-phases instead of halting for `--allow-large`. It is a strict, **fail-fast** variant of the same flow — the family/block loop, the mechanical `verdict-gate-blocks.mjs` terminator, bounds, stuck-detection, and the reports are all **unchanged**; `--auto` only removes the human touchpoints and the local-desktop dependencies:
- **`--mode` is REQUIRED.** The Approach Gate is the one interactive stop, and an unattended run has nobody to ask — so `--auto` **without `--mode` exits immediately** (`HALTED: --auto requires --mode`), it never waits.
- **Design intake is REST** (this is now true for every run — there is no Figma MCP). In `--auto` the token comes from `FIGMA_TOKEN` in the env (no keychain); `figma-extract.mjs rest …` + `enumerate-blocks.mjs rest …` hit `api.figma.com`. No token ⇒ fail-fast.
- **Verification runs in a REAL, logged-in browser — never a blank headless one.** At preflight the orchestrator resolves a real browser CDP endpoint (`scripts/browser-endpoint.mjs` — a Chrome started with `--remote-debugging-port=9222`, or `$VELT_CDP_WS`; `--auto`/cloud launches its own server browser) and pins it as `browserWs`. Every `measure-block.mjs`/`capture-block.mjs` call passes `--connect <browserWs> --require-connect`, so measurement runs in the browser that can actually open the Velt sidebar and **fails loud** if none is provided rather than silently measuring an empty headless surface (the old false-pass). If no real browser is available, the run HALTS with instructions instead of producing a fake "done".
- **Auth is pre-provisioned, not paused.** The target app must already boot into an authed, Velt-rendering state from env/secrets — there is **no** manual-login pause in `--auto`; if Velt doesn't render, preflight fails fast with the reason.
- **Single-context runtimes (e.g. Cursor cloud): CHECKPOINT after the Judge.** Where the whole run shares ONE ever-growing context (no subagent isolation), the fix loop is the expensive tail — every small fix re-processes hours of history. So after the Judge's findings are recorded: commit+push, write the interim handoff, persist the phase state, and release the lock — then prefer re-entering the strict-fix loop in a FRESH turn/session (`resume-check.mjs` re-enters from the journal; verified live on the 2026-07-28 Harvey run, where the resumed fix loop finished in 54 min from a lean context). In Claude Code this is a no-op — the subagent architecture already isolates each dispatch.
- **Every HALT is a clean non-zero exit + a written handoff** (to `progress.log` and the phase handoff), never an interactive wait. Setup MAY run in the background (the heartbeat file already exists from `phase-init.mjs`), so the whole run can be one non-interactive invocation (e.g. `claude -p "/velt-customize-run <url> --mode <approach> --auto"`).

### 2. Run the two-phase build → judge → strict-fix loop — `velt-orchestrator` in **owned-loop mode** (it owns the loop)
**After the approach is set and the coverage matrix is shown**, invoke `velt-orchestrator` in **owned-loop mode**. The full flow is defined ONCE, in the orchestrator agent (Sequences 4–5) — this command only sets it running. The contract:

- **PRIMITIVES BUILD (mode `strictly primitives` only).** Reachability is checked *before* planning (`check-primitive-reachability.mjs`): 392 of 770 wireframe slot positions have no primitive counterpart, so recorder / V1 comment surfaces / reactions / cursor / presence / live-state-sync are reported `mode_blocked` up front rather than ground on. Remaining surfaces go through **velt-planner-primitives** → **velt-builder-primitives** (a compose tree with children/context/state, no wireframe registered), gated on `lint-primitives.mjs` exit 0. Every other mode is unaffected.
- **STRUCTURE BUILD (families sequential, builder mode=structure).** The structure plan (`plan-structure.json` — slots/fills/props/cardinality, NO stylesheet content) is built as a wireframe SKELETON: the **non-flow families build one at a time** (one `velt-builder` each, sequential — they share the wireframe registration + host file, so parallel builders race and stall), then the **flows family builds last**. No cosmetic CSS, no per-block measure-certify loop — self-checks only (lint / tsc / icon-lint / populated render / adoption + binding).
- **DOM SNAPSHOT → STYLE PLAN → STYLE BUILD.** `scripts/dom-snapshot.mjs` mechanically dumps the rendered DOM per state (real tags/classes/paints + overlap/wrapper hints), and `scripts/console-health.mjs` gates console health right there (a ~5s sampled read; a repeating SDK-error storm — e.g. a missing required wireframe prop — is a STRUCTURE defect fixed immediately, never carried into styling or left for the Judge to find hours later); the STYLE planner (`velt-planner-style`, browser read-only) maps the design's VERBATIM values onto snapshot-real selectors → `plan-style.json` (gated by `brief-scaffold.mjs --lint-style` — a guessed selector or a plan-vs-spec value conflict fails HERE, sub-second); the builder in mode=style applies it verbatim (`first-shot-css.mjs` consumes the plan directly).
- **WHOLE-DESIGN JUDGE (once) — `velt-judge-2`.** Fresh context: `judge2-chromatic.mjs` (Figma frame vs live resting + driven hover/selected/focus) **plus chrome probes** (card ring / double border / thread rail / Show-N lines / inter-dialog gap). Agent names findings → `judge2-record-findings.mjs` → `judge-defects.json` `workOrderP0` for Builder. Do **not** use legacy `velt-judge` / `composed-audit` / `emit-judge-defects` for the owned loop.
- **STRICT FIX (iterate until clean or plateau, then blockers).** Each named defect is **iterated until it measures CLEAN or genuinely plateaus** (`block-iter.mjs` governs via `--budget`: strict 6 / balanced 8 / thorough 12 iterations, stopping early on no-progress/oscillation — the STRICT polish-until-match behavior). Fixed → the block advances; **only a truly-plateaued defect → the orchestrator records it on the phase BLOCKERS list** (`report-block.mjs account --disposition BLOCKED --evidence <file>`) and moves on — **no plateau-grinding.**
- After the fix pass: **`scripts/verdict-gate-blocks.mjs`** → `PASS`(0) / `FAIL`(2) / `INCOMPLETE`(3) / `STOPPED`(4), with an **artifact audit** (missing/stale/tampered evidence ⇒ `INCOMPLETE`). **Authority = content-independent `deltaCompare`** (per-element style/box/gap): the design is dummy data and the app is real data, so whole-surface pixel-diff (`visualDiff`) is **advisory only** — it never FAILs on its own, and content differences (comment count, text, names, timestamps) are never defects. A block whose delta spec covered too little (asserted <2 elements, or no inter-card gap on a list surface) is **INCOMPLETE**, not a pass. The run ends only on exit **0** or **4** (a fully-blocker-accounted phase is a clean stop). **Termination is the gate's exit code over script-assembled artifacts — never an agent's "looks matched" claim, never `/goal`.** Pass `--budget strict|balanced|thorough` — it now governs BOTH the phase soft-cap AND the per-defect fix iteration cap (thorough = up to 12 polish iterations per block; recommended for pixel-perfect).

### 3. Handoff + phase completion
When the loop stops (gate 0 or 4), the orchestrator writes the **phase handoff** ([`templates/phase-handoff.md`](../templates/phase-handoff.md)): the `git diff` of `components/velt/ui-customization/`, the per-block disposition table (PASS / BLOCKED / GAP / REMAINING), **the BLOCKERS list — every defect that survived its 2 fix attempts, with its KIND (pixel/scroll/click/hover/console), evidence, and why it couldn't be fixed** (so you can decide which to hand-fix, accept, or escalate to `wireframes + primitives`), what it's uncertain about, what it could NOT verify, exact fix-instruction examples, and a recommendation (say **"phase N complete"** vs instruct a fix). On **"phase N complete"** it snapshots and freezes verified learnings into memory (`node scripts/memory.mjs promote`). To correct a specific mismatch, use `/velt-customize-fix` (surgical edit + re-verify the affected block **and its shared-selector blast radius**).

### (Optional) `/loop` for cadence
You MAY wrap the loop with `/loop` invoking `velt-orchestrator` in **step mode** (one family-round per turn) for transcript visibility. Cosmetic only — the fidelity gate is always `verdict-gate-blocks.mjs`.
