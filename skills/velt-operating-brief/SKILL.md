# velt-customize — operating brief

Turning a Figma design into clean Velt UI customization (comments + notifications, React) via Planner → Builder → Judge — **one phase at a time**, run **in the current project** (cwd; no target-repo argument).

## Phases, Loops, and the Figma template
A **phase = one `Loop` node** (the user passes one Loop URL per invocation). Designs are authored in a fixed template we ask the user to follow:
- **`Loop N`** — the phase. Inside it: **`State`** (component-level states/variants — e.g. Composer States, Comment Thread) and **`Flows`** (assembled full-surface screens, in sequence — e.g. default sidebar → empty state, or double-click → adding comment → submitted).
- `enumerate-blocks.mjs` reads this: `Flows` frames → `role:flow` **acceptance** blocks, `State` frames → `role:state` **component** blocks. It is **surface-agnostic and design-derived** — geometry comes from each frame's own box (no hardcoded width), state from its own label; a Loop of sidebar, dialog, or notification frames all work. Nothing is hardwired to any reference design.
- Work carries across phases via **per-project memory** (`.velt-customize/memory.json`); each phase ends at a **human checkpoint** (handoff → "phase N complete" or fix).

## The one rule that governs everything
**`guide/` is the first source of truth — but its *silence* is not a verdict.** For any decision — which component, layer, identifier, behavior, data field, how to verify, how to handle a blocker — READ the relevant `guide/` file and apply it. Knowledge lives across: identifiers (`reference/*`), **prop behavior & interactions** (`reference/behaviors.md`), **data fields / events / custom-data** (`reference/data-models.md`), and **what a component is *for*** (`reference/component-definitions.md`). When the guide doesn't cover something or you're unsure, **don't guess, don't hedge, don't declare it impossible** — **verify against ground truth**: Velt Docs MCP / official Velt docs → the live SDK's behavior/types → an empirical test in the running app; then state the verified fact (and ideally feed it back into the guide). Never invent a name (R10); never hack (R0).

## Flow (do not skip preflight or the gate)
0. **Preflight (before anything) — fail fast, fail clear, NO fallback.** Check + print a ✓/⚠/✗ readiness summary with a plain-language fix per item: guide present · **Figma token present + the node resolves via REST** (`FIGMA_TOKEN`/keychain → `figma-extract.mjs rest` against `api.figma.com`) · **Velt installed in the repo** · **app runs + Velt renders** (capture the default-UI baseline) · **Cursor's native browser tool reachable** (navigate to the app URL, confirm a snapshot works) · **auth** (never enter creds — manual login → pause and ask) · **`/loop` availability** (optional — cadence only; the orchestrator owns the block loop in `owned-loop` and termination is always `verdict-gate-blocks.mjs`'s exit code, never `/goal`). **Hard items — must pass, no fallback: guide · Figma token+REST resolves · Velt-installed · app+Velt renders · browser tool.** If the Figma token is missing or the node won't resolve → HALT (design intake is REST-only — there is **no** Figma MCP and **no** browser-screenshot fallback); if the browser tool is unavailable → HALT before building. Any ✗ **HALTS with the fix and changes nothing**; translate tool errors into plain language, never dump a raw stack. Only auth/live-app + `/loop` are **deferred/soft** (auth enforced at the gate; manual-login pause is the one safety exception). Idempotent — fix and re-run.
1. **Approach Gate — MANDATORY, never skipped; BEFORE planning (so the planner is constrained).** The approach (`strictly wireframe` | `strictly primitives` | `wireframes + primitives` | `freeform`) is required: taken from `--mode` if supplied, **else HALT and ask the user, presenting your per-surface recommendation** (never auto-pick, never infer silently). Record the mode in the journal + memory. **SETUP guards:** a URL with **no `node-id`** is rejected — HALT and ask for a node-specific **Loop** URL (a file-level URL is a discovery step, not a phase); if enumeration yields **more than ~8 blocks**, warn the Loop may be too large to phase well. This is the one guaranteed user interaction.
2. **Plan (read-only, CONSTRAINED by the chosen mode) — load memory, extract → map → enumerate. The Planner is the BRAIN; go DEEP on RECOGNITION, but BOUNDED** (see [`build-methodology.md`](../../guide/build-methodology.md)). Enumerate first and **surface the block list as a fast checkpoint** before the deep plan (setup is never a silent black box). Depth = recognizing every surface/state + a complete Connect Map — **NOT re-measuring**: the exact numbers come from `figma-extract`'s `designSpec` and the geometry from `blocks.json`; per-element measurement + live-DOM inspection is the **per-block Judge's** job, so don't do it for the whole design up front (that's what made a run grind for 38 min). Keep planning to ~10 min. First **load cross-phase memory** (`node scripts/memory.mjs load`) as an advisory prior (tokens/mappings/naming/corrections) — re-verify anything used against the fresh design; heed `_stale` flags. **From the REST-exported frame PNGs** (`scripts/enumerate-blocks.mjs rest …` → `frames/*.png` for this phase's Loop): go through **every frame** under it, list **all surfaces**, every element, **every state**. Then **EXTRACT the `designSpec` deterministically** (`scripts/figma-extract.mjs rest`, [`extraction.md`](../../guide/extraction.md)) — exact spacing/sizing/radius/typography/colours + the **exported icon SVGs** (R17); numbers are read, never eyeballed. (Design intake is REST-only — there is no Figma MCP.) **Read the host's existing Velt props** as design intent. Recognize via `component-definitions.md`; confirm behavior via `behaviors.md`, data via `data-models.md`. Pick the layer via `02-decision-tree.md` (Q1–Q4 + S1–S8) **within the chosen mode** (`strictly wireframe`/`strictly primitives` → a piece needing the other layer is `mode_blocked`, not silently switched). Then **MAP** (Velt Code Connect, [`reference/manifest.md`](../../guide/reference/manifest.md)): per element → `{slot, slotType, fillWith, hostProps, cssDecls}` — **props-first** (R21) and **supply every `mustSupply` slot** (R19). **List what's NOT supported by default** with the plan for each. Output a **complete, decided Connect Map + designSpec**, each decision tagged `verified/assumed/unknown→verify`. **Then ENUMERATE BLOCKS** (`scripts/enumerate-blocks.mjs` → `blocks.json`): the Loop's `Flows` frames (`role:flow`) + `State` frames (`role:state`, tagged `component`) are the **blocks** — the completeness oracle, design-derived (no hardcoded width). Annotate each block's `state`/`drive`/`fixture`/`liveSelector`/`frameRegion`. Present the coverage matrix under the chosen mode.
3. **Build → Judge loop — BLOCK BY BLOCK, one Figma block perfected before the next; HARNESS-OWNED, terminated MECHANICALLY by `verdict-gate-blocks.mjs` exit code** (see [`build-methodology.md`](../../guide/build-methodology.md) Step 2; read [`build-gotchas.md`](../../guide/build-gotchas.md)). The orchestrator owns a **block queue** from `blocks.json` and advances one block per `step`; it does NOT rely on `/goal` (an LLM opinion over the transcript that let prior runs stop early) — the stop condition is the gate's exit code over persisted artifacts. `/loop` may provide cadence but is never the fidelity gate. **A block is iterated until it PASSes (visual ∧ layout ∧ contract ∧ stability — no interactive target shifts mid-interaction, R27); only then advance.** Per block:
   - **Builder** (maker): one surface at a time (dialog first). **Execute the Connect Map verbatim** — set host props first (R21), **supply every `mustSupply` slot** with the design's exported SVG/text (R19; never a Velt default), build the structure, then apply the map's **exact `cssDecls`** to the real Velt classes (`!important`, R9b) — **don't re-measure or eyeball**. Generate an `icons/` file from the exported SVGs. Prefer the native slot + CSS before a custom variant (P4/R12). Then interactivity/states, then test features functionally, then the next surface, then the unsupported items. Files under `ui-customization/` only (R11/R18); one stylesheet (R8); one `<VeltWireframe>` (R1). Manifest-driven smoke-test before handoff (every `mustSupply` slot supplied; gross-undershoot guard).
   - **Judge** (checker, fresh context — never the maker): for the **current block**, (1) **SEED + DRIVE the block's state IN-APP** (run `block.drive`/`fixture` inside the live app session — pierce the shadow-DOM composer, type into the composer's `[contenteditable]` (resolve the live selector per design — no hardcoded `.hw-*`), click the **visible** send button by coordinate, hover/open as the state needs; wait for `block.drive.assert` before measuring — never capture a half-loaded or wrong state); (2) **CAPTURE device-res** (`scripts/capture-block.mjs` → device-res PNG at DPR-2 = frame-width × 2; NOT the browser tool's ~1× lossy screenshot); (3) **VISUAL DIFF** the capture vs the block's frame with `scripts/visual-diff.mjs --mask-text-from <designSpec>` — chrome-only (text is masked; the frame-width match aligns chrome to ~0%), and **any region with `fill ≥ ~0.05` is a real structural diff ⇒ FAIL** (thin 1px-drift outlines are delta-compare's job, not this); (4) **DELTA-COMPARE** for exact numbers — `scripts/delta-compare.mjs` `BROWSER_PROBE` `{surfaceSelector, tol, elements, relations, gaps}`: live `getComputedStyle` (**style:** ΔE<2, ±1px) AND `getBoundingClientRect` (**layout:** box ±2-3px, gaps, relations, missing/extra). delta-compare owns text/colour/size/position (font-render-immune); visual-diff owns missing/extra/wrong-element structure. For each painted node run **`LAYER_PROBE`** — FAIL on `ownerMismatch` (R23) or any `neutralize[]` (R22). Run **`CONTRACT_PROBE`** on the post-reconciliation DOM (R25) — FAIL on any `MISSING`/`CONTAINMENT`/`CARDINALITY`/`PHANTOM_INTERACTIVE` (a boolean veto regardless of pixels). **No aggregate score; any significant visual region / style / layout / reconciliation / contract violation ⇒ FAIL** with the localized regions + delta rows as feedback. PASS = **visual ∧ layout ∧ contract**. **Hard gates:** console error / unbuilt / `width===0` ⇒ `BLOCKED`/`FAIL`; every `mustSupply` slot present + carrying the design's SVG/content (R17/R19); no feature the design lacks (R24). A non-render → **app-vs-build triage first** (`BLOCKED`, not `FAIL`, when env/auth is the blocker). **The Judge writes its per-block disposition into `block-report.json` and SURFACES the evidence; it NEVER declares the run done — `verdict-gate-blocks.mjs` does, by exit code.**
   - **Two-tier verify (latency fix):** the Judge runs the CHEAP checks (`delta-compare` + `LAYER`/`CONTRACT`/`STABILITY` probes, no screenshot) **every iteration** in one reused live session; the EXPENSIVE `capture-block` + `visual-diff` + icon-identity run **only at iteration 1 and a PASS-candidate**. Icon identity = exact exported-SVG file/shape match first, AI-vision fallback.
   - **Termination = the MECHANICAL `verdict-gate-blocks.mjs` exit code over `blocks.json`, never an agent's say-so.** Each block the Judge writes its disposition into **`block-report.json`**; the orchestrator runs `verdict-gate-blocks.mjs`. It returns `PASS`(0) / `FAIL`(2) / `INCOMPLETE`(3) / `STOPPED`(4). **A run that built fewer blocks, didn't drive a state, or lacks an artifact is `INCOMPLETE` — NOT pass, the loop CANNOT terminate** (the M5 fix). The phase stops on exit **0** (every block PASS, or a verified `BLOCKED`/`GAP` with an evidence note) **or 4** (`STOPPED` — a block `STUCK` at its bounds, or the soft-cap listed un-started blocks in `report.phase.remaining`). This is a script exit code, not `/goal`'s judgment.
   - **Bounds (harness-owned, so a phase can't run for hours):** per block ≤12 iterations or ≤8 min; a retry is accepted only if the failing-diff count **strictly drops**; plateau (2 no-progress) → escalate the layer once → else mark the block `STUCK` (with an evidence note). **Phase soft-cap:** at 60 min stop starting new blocks, let the in-flight block finish within a ~15–20 min grace, then list remaining blocks and stop. **Never declare a gap to escape** — exhaust inspect→override→data-driven→full-container first.
4. **Handoff + phase completion (the human checkpoint).** On stop, write the **phase handoff** ([`templates/phase-handoff.md`](../../templates/phase-handoff.md)): the `git diff` of `ui-customization/`, the per-block disposition table (PASS/FAIL/STUCK/BLOCKED/GAP/REMAINING), what's uncertain, what couldn't be verified, required host changes (R18), fix-instruction examples, and a recommendation (say **"phase N complete"** vs fix a block). On **"phase N complete"**: snapshot + **freeze verified learnings** into memory (`memory.mjs promote` — never failed/tentative/env-workarounds). To correct a mismatch use `/velt-customize-fix` (surgical + blast-radius re-verify). The fuller `velt-customization-report.md`/`sdk-gap-report.md` may follow.

## Hard guardrails
- Verify each surface before the next (R15/R16). A goal is never "met" without evidence.
- Never enter credentials; use the app's existing auth/test harness — if manual login is needed, pause and ask.
- Run in **cwd**; touch only `components/velt/ui-customization/` + the `.velt-customize/` phase dir. **Never change the host app's non-Velt UI or default behavior (R18)** — a required host change is applied temporarily, verified, **reverted**, and reported as a manual step, never baked in. No deletes, no config/build changes, no commits unless asked.
- **The MANDATORY approach is the one guaranteed user interaction** (from `--mode`, else a HALT-and-ask — never auto-picked). Recognition ambiguities, retries, escalations → autonomous; log + surface only in the handoff. (A hard preflight failure halts with a fix; manual-auth pause is a safety exception.)
- **`--cloud` (fully autonomous, headless — Cursor cloud agent / CI):** same flow, **no human touchpoints, no desktop.** `--mode` is REQUIRED (absent ⇒ fail-fast `HALTED: --cloud requires --mode`, never ask); every HALT becomes a clean non-zero exit + written handoff instead of a wait (no manual-login pause). Design intake is already REST-only everywhere; in `--cloud` the token comes from the `FIGMA_TOKEN` env var (no keychain). The one cloud delta is **headless verification** — the Judge drives a headless Chromium (`capture-block.mjs` + `playwright-core` over CDP via `--connect`, or Cursor Cloud's native browser tool); guide · Velt-installed · app-boots-authed-and-Velt-renders stay hard. The block loop + `verdict-gate-blocks.mjs` terminator are unchanged.
- A goal is `met` only on a genuine side-by-side match — never on "structure present" or "looks close". Loop until it truly matches. **The one human override:** the user explicitly saying **"I've checked, it's good for now"** accepts the current state despite a non-clean gate (recorded as human-accepted); nothing else overrides the mechanical gate.
- Never declare an SDK gap to escape the loop — exhaust inspect (to the leaf element) → CSS vars + class `!important` → data-driven (user color/config) → full-container wireframe, with evidence, first.

## Verified facts (don't relitigate — full detail in the guide)
One `<VeltWireframe>` per app · container slots drop undeclared children → declare the full tree · `ThreadCard` MUST nest in `Body → Threads` · root wireframe auto-removes shadow, nested-only needs `shadowDom={false}` · CSS variables cross shadow, class CSS doesn't · pin index/number slots are empty → fill via `velt-data` · use `VeltCommentDialog`, never the deprecated `VeltCommentThread`.

## When unsure
Read the guide file. If the guide is silent, **verify against ground truth** (Velt Docs MCP / official docs → live SDK → running app) — don't guess or hedge. Only a capability that is genuinely absent *after that verification* (e.g. a field the data model doesn't store) is an SDK gap (`guide/sdk-gaps-and-blockers.md`) — never a hack, and never a guess.
