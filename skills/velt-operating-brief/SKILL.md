# velt-customize — operating brief

Turning a Figma design into clean Velt UI customization (comments + notifications, React) via Planner → Builder → Judge — **one phase at a time**, run **in the current project** (cwd; no target-repo argument).

## Phases, Loops, and the Figma template
A **phase = one `Loop` node** (the user passes one Loop URL per invocation). Designs are authored in a fixed template we ask the user to follow:
- **`Loop N`** — the phase. Inside it: **`State`** (component-level states/variants — e.g. Composer States, Comment Thread) and **`Flows`** (assembled full-surface screens, in sequence — e.g. default sidebar → empty state, or double-click → adding comment → submitted).
- `enumerate-blocks.mjs` reads this: `Flows` frames → `role:flow` **acceptance** blocks, `State` frames → `role:state` **component** blocks. It is **surface-agnostic and design-derived** — geometry comes from each frame's own box (no hardcoded width), state from its own label; a Loop of sidebar, dialog, or notification frames all work. Nothing is hardwired to any reference design.
- Work carries across phases via **per-project memory** (`.velt-customize/memory.json`); each phase ends at a **human checkpoint** (handoff → "phase N complete" or fix).

## The one rule that governs everything
**Read the guide TARGETED, never whole.** Every agent routes its guide reads through `node scripts/guide-lookup.mjs files --role <plan|build|judge> [--approach …] [--feature …] [--surface …]` and reads only that list; the big reference files it marks `[SECTION-INDEXED]` are read only via `guide-lookup.mjs section <file> "<term>"` for the specific components/slots/classes in play. The guide corpus is ~16k lines — pulling whole reference pages into every subagent is the main token/latency leak.

**`guide/` is the first source of truth — but its *silence* is not a verdict.** For any decision — which component, layer, identifier, behavior, data field, how to verify, how to handle a blocker — READ the relevant `guide/` file and apply it. Knowledge lives across: identifiers (`reference/*`), **prop behavior & interactions** (`reference/behaviors.md`), **data fields / events / custom-data** (`reference/data-models.md`), and **what a component is *for*** (`reference/component-definitions.md`). When the guide doesn't cover something or you're unsure, **don't guess, don't hedge, don't declare it impossible** — **verify against ground truth**: Velt Docs MCP / official Velt docs → the live SDK's behavior/types → an empirical test in the running app; then state the verified fact (and ideally feed it back into the guide). Never invent a name (R10); never hack (R0).

## Flow (do not skip preflight or the gate)
0. **Preflight (before anything) — fail fast, fail clear, NO fallback.** Check + print a ✓/⚠/✗ readiness summary with a plain-language fix per item: guide present · **Figma token present + the node resolves via REST** (`FIGMA_TOKEN`/keychain → `figma-extract.mjs rest` against `api.figma.com`) · **Velt installed in the repo** · **app runs + Velt renders** (capture the default-UI baseline) · **Cursor's native browser tool connected** · **auth** (never enter creds — manual login → pause and ask) · **`/loop` availability** (optional — cadence only; the orchestrator owns the block loop in `owned-loop` and termination is always `verdict-gate-blocks.mjs`'s exit code, never `/goal`). **Hard items — must pass, no fallback: guide · Figma token+REST resolves · Velt-installed · app+Velt renders · Cursor browser tool.** If the Figma token is missing or the node won't resolve → HALT (design intake is REST-only — there is **no** Figma MCP and **no** Chrome-screenshot fallback); if the Cursor browser tool is down → HALT before building. Any ✗ **HALTS with the fix and changes nothing**; translate tool errors into plain language, never dump a raw stack. Only auth/live-app + `/loop` are **deferred/soft** (auth enforced at the gate; manual-login pause is the one safety exception). Idempotent — fix and re-run. **STRICT (part of "app runs"): resolve the ACTUAL dev-server URL for this run — NEVER assume `localhost:3000`** (ports auto-bump when taken — Next/CRA → 3001+, Vite → 5173+ — projects override them, and another project's server may be squatting on 3000): read the URL from the dev server's own startup output (or `node scripts/preflight-env.mjs` lists listening ports — it ALSO scans `/etc/hosts` for `*.velt.dev` hijacks, a hazard that cost two runs ~40 min), confirm the responder is THIS repo's app **mechanically via `node scripts/verify-app.mjs <url> --expect "<marker>"`** (a prior run judged the wrong project for ~35 min on an unverified :3000), and **pin it as `appUrl` in the run journal** — every later navigation/probe/capture uses the pinned `appUrl`, never a re-guessed port. Once pinned, start `node scripts/env-watchdog.mjs <phaseDir> <appUrl> --restart-cmd "<dev cmd>" &` in the background: it freezes budgets (`block-iter pause`) the moment the env dies, auto-restarts + re-verifies + resumes, and flags dead/wedged agents — env dead-time never burns build budget.
1. **Approach Gate — MANDATORY, never skipped; BEFORE planning (so the planner is constrained).** The approach (`strictly wireframe` | `strictly primitives` | `wireframes + primitives` | `freeform`) is required: taken from `--mode` if supplied, **else HALT and ask the user, presenting your per-surface recommendation** (never auto-pick, never infer silently). Record the mode in the journal + memory. **SETUP guards:** a URL with **no `node-id`** is rejected — HALT and ask for a node-specific **Loop** URL (a file-level URL is a discovery step, not a phase); if enumeration yields **more than ~8 blocks**, warn the Loop may be too large to phase well. This is the one guaranteed user interaction.
2. **Plan (read-only, CONSTRAINED by the chosen mode) — load memory, extract → map → enumerate. The Planner is the BRAIN; go DEEP on RECOGNITION, but BOUNDED** (see [`build-methodology.md`](../../guide/build-methodology.md)). Enumerate first and **surface the block list as a fast checkpoint** before the deep plan (setup is never a silent black box). Depth = recognizing every surface/state + a complete Connect Map — **NOT re-measuring**: the exact numbers come from `figma-extract`'s `designSpec` and the geometry from `blocks.json`; per-element measurement + live-DOM inspection is the **per-block Judge's** job, so don't do it for the whole design up front (that's what made a run grind for 38 min). Keep planning to ~10 min. First **load cross-phase memory** (`node scripts/memory.mjs load`) as an advisory prior (tokens/mappings/naming/corrections) — re-verify anything used against the fresh design; heed `_stale` flags. **From the REST-exported frame PNGs** (`scripts/enumerate-blocks.mjs rest …` → `frames/*.png` for this phase's Loop): go through **every frame** under it, list **all surfaces**, every element, **every state**. Then **EXTRACT the `designSpec` deterministically** (`scripts/figma-extract.mjs rest`, [`extraction.md`](../../guide/extraction.md)) — exact spacing/sizing/radius/typography/colours + the **exported icon SVGs** (R17); numbers are read, never eyeballed. (Design intake is REST-only — there is no Figma MCP.) **Read the host's existing Velt props** as design intent. Recognize via `component-definitions.md`; confirm behavior via `behaviors.md`, data via `data-models.md`. Pick the layer via `02-decision-tree.md` (Q1–Q4 + S1–S8) **within the chosen mode** (`strictly wireframe`/`strictly primitives` → a piece needing the other layer is `mode_blocked`, not silently switched). Then **MAP** (Velt Code Connect, [`reference/manifest.md`](../../guide/reference/manifest.md)): per element → `{slot, slotType, fillWith, hostProps, cssDecls}` — **props-first** (R21) and **supply every `mustSupply` slot** (R19). **List what's NOT supported by default** with the plan for each. Output a **complete, decided Connect Map + designSpec**, each decision tagged `verified/assumed/unknown→verify`. **Then ENUMERATE BLOCKS** (`scripts/enumerate-blocks.mjs` → `blocks.json`): the Loop's `Flows` frames (`role:flow`) + `State` frames (`role:state`, tagged `component`) are the **blocks** — the completeness oracle, design-derived (no hardcoded width). Annotate each block's `state`/`drive`/`fixture`/`liveSelector`/`frameRegion`. Present the coverage matrix under the chosen mode.
3. **Build → Judge loop — BUILD BY FAMILY, VERIFY PER BLOCK (R16), SCRIPT-OWNED.** The full flow lives in ONE place — the `velt-orchestrator` agent (Sequence 5) — do not re-derive it here. The load-bearing facts:
   - **Loop state is owned by `scripts/block-iter.mjs`** (iterations, active-minutes with **env stalls excluded** via `pause`/`resume` — the watchdog opens/closes them, plateau/oscillation from a **controller-computed** git-diff hash, the one layer-escalation, auto-written STUCK, phase soft-cap; `--budget strict|balanced|thorough`). Agents obey its exit codes; nobody counts, keeps time, or hands in a hash from memory. All timestamps are UTC.
   - **One Builder invocation per FAMILY** (`blocks.json families[]`; flows last): `first-shot-css.mjs` writes the Connect Map's exact numbers as the stylesheet BEFORE any patching; the family's wireframe subtree is built once covering every state; each block then runs the **`measure-block.mjs` self-certify loop** (the SAME pipeline the audit uses — reset/drive from the block's probe brief → capture → visual-diff → delta/LAYER/CONTRACT/STABILITY probes → `report-block.mjs` assembly), executing the Connect Map verbatim (props-first R21, every `mustSupply` slot R19, exact `cssDecls` R9b) with `lint-customization.mjs` + the render smoke-test in its handoff gate.
   - **The Judge (fresh context) is invoked at TWO points per family** — first structural build (gross-structure catch, `measure-block --structure-only`) and the family audit (fresh `measure-block` re-runs per block + **icon identity** — only after which `--accept-glyph-residuals` R29 may apply — + the family's **real-path smoke suite** `measure-block smoke` R30). It never hand-writes `block-report.json`. PASS = visual ∧ layout ∧ contract ∧ stability ∧ smoke; no aggregate score; hard gates (render, `mustSupply` R17/R19, R24) apply regardless of pixels.
   - **Termination = `verdict-gate-blocks.mjs` exit code** over the script-assembled artifacts (its audit rejects hand-written entries, missing/stale PNGs, report-vs-artifact mismatches, any STUCK/BLOCKED/GAP without an existing evidence file, and a family missing its smoke artifact). `INCOMPLETE` can never terminate (R26); `/goal` never decides. GAP/BLOCKED are recorded only via `report-block.mjs account --evidence <file>` — never a shortcut out of the loop. Leftover residuals/STUCK at gate 0/4 → ONE **batched fix pass**, then a re-audit of the touched blocks + blast radius.
4. **Handoff + phase completion (the human checkpoint).** On stop, write the **phase handoff** ([`templates/phase-handoff.md`](../../templates/phase-handoff.md)): the `git diff` of `ui-customization/`, the per-block disposition table (PASS/FAIL/STUCK/BLOCKED/GAP/REMAINING), what's uncertain, what couldn't be verified, required host changes (R18), fix-instruction examples, and a recommendation (say **"phase N complete"** vs fix a block). **Also at every stop: auto-promote journaled learnings as TENTATIVE** (`memory.mjs promote --tier tentative` — the old confirm-only flow meant zero learning ever persisted). On **"phase N complete"**: snapshot + `memory.mjs confirm --phase <id>` (tentative → confirmed; never failed attempts or env-workarounds). To correct a mismatch use `/velt-customize-fix` (surgical + blast-radius re-verify). The fuller `velt-customization-report.md`/`sdk-gap-report.md` may follow.

## Hard guardrails
- Verify each surface before the next (R15/R16). A goal is never "met" without evidence.
- Never enter credentials; use the app's existing auth/test harness — if manual login is needed, pause and ask.
- Run in **cwd**; touch only `components/velt/ui-customization/` + the `.velt-customize/` phase dir. **Never change the host app's non-Velt UI or default behavior (R18)** — a required host change is applied temporarily, verified, **reverted**, and reported as a manual step, never baked in. No deletes, no config/build changes, no commits unless asked.
- **The MANDATORY approach is the one guaranteed user interaction** (from `--mode`, else a HALT-and-ask — never auto-picked). Recognition ambiguities, retries, escalations → autonomous; log + surface only in the handoff. (A hard preflight failure halts with a fix; manual-auth pause is a safety exception.)
- **`--auto` (fully autonomous — headless cloud/CI or a local unattended run; legacy alias `--cloud`):** same flow, **no human touchpoints, no desktop, no going stale.** `--mode` is REQUIRED (absent ⇒ fail-fast `HALTED: --auto requires --mode`, never ask); every HALT becomes a clean non-zero exit + written handoff instead of a wait (no manual-login pause); an oversized Loop **auto-splits by family** into ≤8-block sub-phases instead of waiting on `--allow-large`; an in-flight phase auto-resumes from the journal; the env watchdog with `--restart-cmd` is mandatory and dead/wedged subagents are respawned without asking. Design intake is already REST-only everywhere; in `--auto` the token comes from the `FIGMA_TOKEN` env var (no keychain). Verification is headless — a headless Chromium (`playwright-core`), all pipelines via `measure-block.mjs --connect`; guide · Velt-installed · app-boots-authed-and-Velt-renders stay hard. The family/block loop + `verdict-gate-blocks.mjs` terminator are unchanged.
- A goal is `met` only on a genuine side-by-side match — never on "structure present" or "looks close". Loop until it truly matches. **The one human override:** the user explicitly saying **"I've checked, it's good for now"** accepts the current state despite a non-clean gate (recorded as human-accepted); nothing else overrides the mechanical gate.
- Never declare an SDK gap to escape the loop — exhaust inspect (to the leaf element) → CSS vars + class `!important` → data-driven (user color/config) → full-container wireframe, with evidence, first.

## Verified facts (don't relitigate — full detail in the guide)
One `<VeltWireframe>` per app · container slots drop undeclared children → declare the full tree · `ThreadCard` MUST nest in `Body → Threads` · root wireframe auto-removes shadow, nested-only needs `shadowDom={false}` · CSS variables cross shadow, class CSS doesn't · pin index/number slots are empty → fill via `velt-data` · use `VeltCommentDialog`, never the deprecated `VeltCommentThread`.

## When unsure
Read the guide file. If the guide is silent, **verify against ground truth** (Velt Docs MCP / official docs → live SDK → running app) — don't guess or hedge. Only a capability that is genuinely absent *after that verification* (e.g. a field the data model doesn't store) is an SDK gap (`guide/sdk-gaps-and-blockers.md`) — never a hack, and never a guess.
